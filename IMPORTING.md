# Moving in: the Excel-first kits

Both kits run on Base import-kit (`src/modules/import-kit`, D1 port). Each one
previews without writing, commits only the fingerprint finance reviewed, keeps
the exact original file bytes in the journal, applies in bounded batches that
can be continued, and undoes through the journal. Each import has its own
destination (`actuals:<digest>` or `workbook:<digest>`) so undo touches only
what that import wrote. Nothing is sent back to, or cancels, the system the
file came from.

## Actuals: general-ledger detail CSV

The documented shape is one row per posted ledger line with a heading row.
Choose the columns in the preview; Easel suggests them from common headings.

| Column | Required | Notes |
|---|---|---|
| Date or Period | yes | Date as DD/MM/YYYY, YYYY-MM-DD or MM/DD/YYYY; or a YYYY-MM period column |
| Account code | yes | Mapped to a planning line, the cash balance, or excluded |
| Account name | no | Shown beside the code |
| Department / tracking | no | Mapped to an Easel department or "No department" |
| Debit and Credit, or Amount | yes | Separate columns, or one column with debits positive or credits positive |
| Description, Reference | no | Kept and cited in variance drafts |

Limits: 2 MB and 5,000 rows per file (split larger exports by month). Rejected
rows (malformed date or amount, no account, both debit and credit, an exact
repeat of an earlier line unless you say identical rows are separate
transactions, a row already accepted in another import) are listed with their
line numbers and stay out only after you confirm. Amounts are stored
debit-positive in cents; reports show revenue and costs as positive numbers
through the account mapping. Remapping an account changes how existing
actuals are classified everywhere except in approved budgets, kept forecasts
and published packs, which keep their numbers. An import used by a closed
month cannot be undone; import a correcting file instead.

`fixtures/gl-detail-2026-07.csv` and `fixtures/gl-detail-2026-08.csv` are
synthetic examples of this shape (including one repeated and one malformed row).
They are not exports from any real company or accounting product.

## Planning workbook: .xlsx

One sheet with a heading row (within the first 20 rows) containing `Line`,
`Department` and one column per month, headed like `Jul-26`, `Jul 2026`,
`2026-07` or an Excel date. Values are natural signs: revenue and costs both
positive.

- Easel reads each cell's cached value (what Excel last calculated). Formulas
  are kept as text in the cell's provenance and are not translated or run.
- Values are rounded to cents; the preview counts any that needed rounding.
- Rows whose line or department starts with "Total" are skipped (Easel
  calculates totals); empty cells stay missing, not zero; text or error cells
  reject the row.
- Every line and department name must match Easel's or be mapped in the preview.
- Months outside the plan year are listed and ignored.

The import becomes a new scenario of monthly schedules, each keeping file,
sheet, row and the cell address of every month. Compare it with the budget,
adopt it into a working plan (Scenarios → "Use as …") or undo it. Undo keeps
any schedule someone has since edited, and the scenario it belongs to.

`fixtures/fy27-budget.xlsx` is a synthetic workbook in this shape, generated by
`fixtures/build-workbook.mjs` (formulas with cached values, a total row, a name
that needs mapping and values that need rounding).

Later kits (Cube, Pigment, Adaptive, Planful, Anaplan exports) wait for
representative owner-authorized exports; generic CSV intake is not a certified
importer for any of them.
