# Reviewing committed spend

Finance connects Ramp and Purse under Settings. Use a Ramp credential restricted to transaction reads and a Purse token with `read-purchase-orders` for the selected suppliers. The installation owner configures `PURSE_ORIGIN` as its HTTPS origin. Easel makes only GET requests, never follows provider redirects and never initiates purchases or payments. Credentials are sealed and excluded from both open exports and owner archives. A restored installation must reconnect.

In Review, open Committed spend. Choose an accounting month and explicit Purse PO IDs, then read the sources. Ramp cleared transactions are selected by that accounting period. Purse reads use the existing individual-order integration door; there is no invented listing permission. Pending and declined cards do not count as actual spend. Only issued POs are supported by this initial slice.

Choose a dedicated one-off expense in the working company forecast. Its line, department and month become the explicit mapping for the reviewed rows. Select a PO for each card that pays that obligation; leave it separate when it is unrelated. Review the source dates and amounts before previewing. An accepted card is counted once as card actual; its explicit PO link reduces that PO's open commitment by the same amount. A PO bill alone is not payment evidence.

The preview reads the immutable approved budget. Remaining equals budget minus card actual minus open commitment. Acceptance replaces the chosen expense assumption with card actual plus open commitment; it does not add a second expense or create ledger actuals. Re-reading the same source updates that same assumption. A changed source, mapping or scenario revision requires another preview. A source already assigned to another driver is refused. Mixed forecast cells, accepted ledger overlap, closed months, unsupported currencies, excess PO payments and incomplete provider reads are refused rather than guessed.

Accepted reviews retain their source figures after disconnect. Later forecast edits are marked as requiring review again. Disconnect always deletes the local sealed credential and records that remote revocation is unsupported; the connection screen gives the provider's explicit owner revocation step. Revoke the credential in the source application to end its provider authority.

This initial connector slice has network-edge fixture qualification only. Live Ramp and Purse qualification, broader committed contracts, Coaster expense reports, Brex, Bill.com, refunds, PO closure releases, bill-payment settlement and ledger reconciliation remain unfinished. Requested source scopes are operator instructions; a live provider grant has not been qualified. No provider credentials are provisioned by the example fixtures.

Ramp amounts use the structured `entity_amount` settlement currency and integer minor-unit value; deprecated bare transaction amounts are never scaled or guessed. See [Ramp monetary values](https://docs.ramp.com/developer-api/v1/monetary-values). Ramp token revocation requires application client credentials, which this pasted-token slice does not store; the explicit owner step remains required.
