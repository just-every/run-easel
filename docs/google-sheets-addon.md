# Google Sheets live-data add-on

The Editor add-on source ships at `/google-sheets/Code.gs`, with `Sidebar.html` and `appsscript.json` beside it. It provides `EASEL_VALUE` and `EASEL_REPORT`, menu refresh, installable open refresh, an hourly installable trigger that opens saved spreadsheet IDs while closed, and exact-revision write-back through the same grid/proposal commands as Excel. Google custom function identifiers use underscores; these are the Sheets equivalents of Excel’s `EASEL.VALUE` and `EASEL.REPORT`.

## Install and connect

1. In a Google Workspace test domain, create an Apps Script Editor add-on project. Copy the three files, retaining the `Sidebar` HTML filename. Enable the manifest in Project Settings and replace it with the shipped manifest. Create an Editor add-on test deployment for the spreadsheet, authorize it and open **Extensions → Easel**. This source is ready for test deployment; Marketplace publication is a separate Google process.
2. Sign in to Easel natively first. Finance opens **Settings → Google Sheets add-on**, chooses that existing person and the spreadsheet ID from its URL, reviews read/write scope, lifetime and refresh schedule, and creates the connection. Give the non-secret confirmation link to that person. They sign in natively, review the approved spreadsheet/scope and claim their own once-shown key, then copy it into their add-on sidebar with the trusted HTTPS Easel installation origin. Finance cannot claim another person’s key. No browser session or general API token is transferred.
3. Connecting installs an authorized open trigger. When finance has approved hourly refresh, it also installs a time-driven trigger. After finance changes a schedule, use **Sync refresh triggers** in the sidebar. Disabling hourly refresh in Easel takes effect at the next request even if a Google trigger remains installed. Google controls dispatch timing; hourly means a Google hourly trigger, not an exact minute SLA.

The manifest requests spreadsheet read/write (needed to open the saved document while closed and update refresh results), external requests to the chosen Easel origin, trigger management and the editor sidebar. Google’s spreadsheet scope is broader than a single sheet; review that Google authorization. Easel independently binds each key to one spreadsheet. Apps Script installable triggers run as their creator, including an open trigger fired when another editor opens the file. They use the creator’s connected Easel person, not the opener’s identity. Finance must approve the spreadsheet’s sharing audience before publishing aggregates into it. Each user can connect their own finance-issued key and refresh with their own current authority. A viewer’s refresh never gains the creator’s Easel authority.

## Formulas and refresh

Use **Insert a live formula** to select a destination and insert either function:

```
=EASEL_VALUE("Revenue","Sales","2026-01","<scenario-id>",'_Easel_Data'!$A$1)
=EASEL_REPORT("<report-id>","2026-01","budget",'_Easel_Data'!$A$1)
=SUM(A1:B1)
```

Selectors are literal strings. A line/department accepts a stable ID or unambiguous exact name; versions and reports use stable IDs. Reports return a two-column aggregate table with currency labels, following the saved report’s current audience and source rules. Choose empty spill space. Amounts returned by VALUE are currency decimals; Easel computes in integer cents. Ordinary sheet formulas, including SUM, remain Google’s formulas.

Custom functions cannot make an authorized Easel request in Google’s calculation sandbox. Authorized menu/open/time handlers discover the literal Easel formulas, clear the old cache, read all bindings from Easel and write a hidden `_Easel_Data` cache. Updating its explicit A1 dependency makes the custom functions and downstream sheet formulas recalculate. No volatile NOW/RAND dependency or developer rerun is needed. Refused, missing, malformed, oversized or failed reads clear previous successes; they do not return a successful zero. Every sheet is scanned, with at most 100 distinct bindings. Other formulas and cells are untouched. The hidden sheet is a shared data cache, not an access boundary; hiding it does not protect document data.

Refresh requests contain selectors only. The response contains aggregate cents or a filtered report table and the source revision; no original inputs, employee names, salaries, source rows or traces cross this door. Current native membership, departments, dimensions, report audience, scenario sharing and pay grants apply, intersected with the connection’s issuance ceiling. Changing a person’s role requires a new connection rather than silently increasing its authority. Removing a grant takes effect immediately. No successful response is cached by the Easel API.

## Write-back

The sidebar’s separate reviewed input form sends an existing input row ID, working scenario ID, reviewed scenario revision, month and decimal amount. It never writes back formula/cache cells automatically. A contributor’s requested or returned budget submission receives a direct entry attributed to them at the next revision. Submitting includes that entry. A later write creates and submits a proposal bound to the exact target revision, leaving the working target unchanged. Finance promotes that proposal through the existing native review. Viewer, foreign department, stale revision, calculated cell, closed actual, approved budget and kept forecast writes refuse with a reason. Pay and dimension permissions still apply. Unknown transport outcomes never retry a write; inspect the plan/proposals and refresh before deciding what to do.

## Custody and disconnect

Easel creates a 256-bit key, seals it with installation-bound AES-GCM under a provider-specific purpose in `e_connection_secrets`, and returns it only once to the named native person after they confirm finance’s approved connection. Finance receives a non-secret confirmation link; even finance cannot claim another person’s key. The table is excluded from open and `rer export` archives. Connections shows only its suffix and scope, finance owner, person, schedule, expiry, refresh/count/error/rate-limit status and revocation outcome. Connect, native-person confirmation, disconnect, schedule changes, refresh and actual input/proposal changes are audited with the person and connection identity. Connection administration requires native finance with the connections grant, origin and live session/model fences. Claiming an approved key requires the named person’s own native session and the same origin/revision fences. API tokens, add-on keys, contributors and viewers cannot administer it. Add-on keys work only at the three dedicated add-on routes; they cannot approve, promote or use other API routes.

On Google’s side the key is stored only in Apps Script **UserProperties**, outside the shared document and cache. The Google platform controls that storage and its at-rest protections; this harness cannot qualify Google’s infrastructure. Do not share the Apps Script project or paste keys into cells. Google’s runtime OAuth authorization is managed by Google; Easel stores no Google OAuth credential for this add-on. Native disconnect is authoritative revocation of the Easel-issued key, deletes local ciphertext and blocks future trigger reads/writes. The UI explicitly requires removing the separate Google authorization in **Google Account → Security → Third-party connections** and deleting Apps Script triggers; it never claims Google revoked that authorization. **Remove local connection** in the add-on removes the current user’s key and document-open trigger, removes the hourly trigger when no documents remain, clears the shared cache, and instructs finance to revoke the native key. Removing a Google authorization alone does not revoke the Easel key. Restored installations have no add-on secrets and require reconnection.

## Proof and remaining external qualification

`tests/google-sheets-addon.test.mjs` runs the shipped `.gs` code in an Apps Script platform harness against a real running Easel Worker/D1 and native authentication. Two public-door sanity journeys cover live functions/report ranges and SUM, menu/open/closed-sheet trigger refresh, viewer filtering, direct and proposal write-back, immutable/foreign/stale/Pay refusals, sealed/excluded custody, administration, schedule and revocation. The host supplies Google service boundaries and a small independent dependency calculator; it proves Easel and adapter semantics, not Google’s calculation engine. `tests/google-sheets-addon-browser.mjs` runs the production native connection UI, separate person confirmation, direct entry read back in Plan and the shipped sidebar at 1440 and 390; assertions are at 1440.

The only remaining acceptance qualification is the recorded run in a Google Workspace test domain: install/authorize the Editor add-on, prove Google’s actual custom function/dependency calculation after menu and open refresh, close the document and fire/wait for the installed hourly trigger, reopen to the already-refreshed change, refresh as a viewer, and record Google-managed custody/authorization and trigger lifecycle. No Workspace test-domain account was supplied. No clause status or acceptance judgment is changed by this implementation.
